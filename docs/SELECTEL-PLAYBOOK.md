# Первый Пилот: перенос публичного архива в Selectel

Подготовлено 13 сентября 2026. Это план запуска, а не отчёт о выполненном переносе. Исходники восстановлены из локального журнала операций. Публичная сборка предназначена для Selectel; инфраструктура ещё не переключена. Backend загрузки Selectel требует интеграционной проверки перед включением.

## 1. Ограничение домена и выбранная схема

Selectel CDN не принимает основной домен второго уровня; S3 также допускает пользовательские домены только третьего уровня и выше. Поэтому нельзя напрямую привязать `pilot-archive.ru` к этим сервисам. CNAME flattening сам по себе это ограничение продукта не снимает.

Источники: [домены CDN](https://docs.selectel.ru/cdn/resources/domains/), [домены S3](https://docs.selectel.ru/s3/manage/manage-user-domains/).

Чтобы сохранить адрес без префикса, предлагаемая поправка:

| Компонент | Размещение |
| --- | --- |
| Сайт `pilot-archive.ru` | Selectel S3; небольшой сервер с HTTPS проксирует основной домен в публичный бакет |
| Публичные PDF, обложки, каталог | Публичный бакет Selectel S3 |
| Неодобренные загрузки | Отдельный приватный бакет Selectel S3 |
| Вход, загрузка, проверка | `pilot-archive.pages.dev`, Pages Functions и Cloudflare Access |
| Метаданные и очередь публикации | Существующая D1 |
| Старые файлы R2 | Сохраняем до проверенной миграции |

Публичный сервер обслуживает `/archive/*` через российское S3 с фиксированным адресом upstream. Он не должен проксировать Cloudflare. CDN для файлов можно добавить позже через `files.pilot-archive.ru`; адрес сайта останется прежним. Это добавляет стоимость сервера: до его создания подтвердить конфигурацию и цену в панели. Альтернатива без сервера — изменить требование и использовать `www.pilot-archive.ru`.

## 2. Подготовить код до переключения DNS

- Убрать PDF и полноразмерные JPEG страниц из сборки сайта. Сначала сохранить исходники и перенести файлы, затем менять сборку.
- Хранить загруженный пользователем PDF без повторного сжатия. Отдельно создавать небольшую обложку.
- Рендерить страницы и миниатюры через PDF.js по мере приближения к видимой области. Освобождать canvas за пределами окна чтения. Сохранить режимы листа, прокрутки и разворотов, одиночные обложку и последнюю страницу.
- Раздавать PDF.js, его worker, необходимые ресурсы и шрифты вместе с фронтендом, без обязательных внешних CDN.
- Получать опубликованный каталог из `/archive/manifest.json`. Публичный посетитель не должен обращаться к Cloudflare API.
- Кнопки входа и загрузки ведут на полноценную страницу админки `pilot-archive.pages.dev`. Не выполнять защищённые Access запросы через cross-origin fetch с российского сайта.
- Разделить деплой интерфейса и публикацию архива: деплой не перезаписывает manifest и PDF.
- Для каждой записи хранить её backend: старые файлы R2 не должны автоматически считаться Selectel-файлами после установки новых секретов.

### Надёжность загрузки и публикации

1. Backend создаёт черновик и временную подписанную ссылку на уникальный ключ в приватном бакете.
2. Браузер отправляет PDF в S3, затем вызывает подтверждение завершения.
3. Backend проверяет наличие, размер и формат, фиксирует неизменяемый объект для модерации; только тогда запись становится ожидающей проверки.
4. При недоступности backend файл остаётся приватным. Повторное подтверждение завершает ту же заявку без повторной загрузки. Черновик и идентификатор восстановления сохраняются между перезагрузками страницы.
5. Одобрение запускает повторяемую публикацию: PDF и обложка копируются в публичное хранилище, проверяются, затем обновляется каталог. Ошибка любого шага не приводит к ложному сообщению об успешной публикации.
6. Задания публикации хранятся в D1 и повторяются по расписанию. Обновления каталога сериализуются, чтобы параллельные одобрения не теряли выпуски.
7. Отклонённый файл удаляется не раньше семи суток после отклонения. Срок считается от отказа, а не загрузки. Зависшие черновики очищаются отдельным правилом.

## 3. Что сделать в Selectel

1. Создать проект и два бакета в одном пуле: приватный для заявок и публичный для одобренного архива. Названия выбрать свободные; записать пул, endpoint и имена.
2. Создать сервисного пользователя и S3-ключи с доступом только к этим бакетам. Секретный ключ сохранить в менеджере паролей и секретах backend; не в Git и не во фронтенде.
3. Настроить CORS приватного бакета: origin `https://pilot-archive.pages.dev`, методы PUT/GET/HEAD по фактически используемым операциям, необходимые Content-Type и x-amz-* заголовки; expose ETag. Включить Virtual-Hosted addressing, необходимый для CORS. Уточнить точные заголовки по реализации подписи и сетевому тесту. [Документация CORS](https://docs.selectel.ru/s3/buckets/cors/).
4. Проверить, что приватный объект недоступен без подписи; CORS не заменяет проверку прав доступа.
5. Организовать публичные ключи `issues/<id>/<version>/issue.pdf`, `cover.webp` и отдельно `manifest.json`. Неизменяемым версиям можно задавать длительный кэш; каталогу — короткий TTL или обязательную перепроверку.
6. Настроить удаление отклонённых файлов отдельным заданием по времени отказа. Если применяется lifecycle по префиксу `rejected/`, сначала проверить поддержку, копирование и дату отсчёта; не применять семидневное удаление ко всему бакету.
7. После согласования сервера создать его с публичным IPv4. Открыть 80/443 для посетителей, SSH ограничить; настроить автоматическое продление TLS и перезапуск веб-сервиса.
8. Раздавать frontend и `/archive/*` из публичного S3 через конфигурацию `deploy/Caddyfile`. Установить `S3_PUBLIC_HOST` в публичный hostname бакета из панели (без протокола). Передавать Range, сохранять Content-Type и статусы 206/404. Для архива не применять fallback на index.html; для клиентских маршрутов интерфейса он может быть нужен.
9. Разворачивать сборки в отдельных каталогах с переключением текущей версии. Не использовать удаляющую синхронизацию по корню бакета с выпусками.

## 4. Что сделать в Cloudflare

1. Сохранить Pages-проект `pilot-archive`, D1 `pilot_archive` и R2 `pilot-archive-issues`.
2. Сделать экспорт D1 и резервную копию существующих файлов перед миграцией.
3. Проверить Access на страницах входа/загрузки/модерации и всех `/api/admin/*`, включая альтернативные deployment-адреса. На backend проверять подлинность Access JWT и роли; не доверять произвольному email-заголовку.
4. Сохранить настройки кураторов, волонтёров, PUBLIC_SUBMISSIONS и блокировок. Публичная подача заявки не означает право её одобрить.
5. Добавить секреты Selectel: access key, secret key, endpoint, region, private bucket и public bucket. Точные имена определяются после проверки репозитория. Регион не угадывать по названию страны.
6. Применить проверенные миграции D1: backend объекта, стадии загрузки/публикации, время отказа, задания повторной публикации. Не удалять старые столбцы/данные на первом этапе.
7. Задеплоить админку; отдельно развернуть обработчик расписания, если он сделан как Worker. Проверить, что у него есть нужные bindings и секреты.
8. Пока не менять DNS, выполнить тестовую загрузку и одобрение в Selectel. Убедиться, что новый выпуск появился в российском каталоге без деплоя сайта.

## 5. Миграция существующих выпусков

Составить перечень статических PDF и одобренных объектов R2. Для каждого сохранить идентификатор, метаданные, размер и контрольную сумму; скопировать PDF и обложку в S3, проверить содержимое. Включать в новый каталог только проверенные объекты. Сохранить адреса года/номера/листа и исключить дубликаты по выпуску. Не удалять R2 и исходные PDF после первой успешной копии.

## 6. Проверки перед запуском

- Сайт открывается и листает PDF при заблокированных запросах к Cloudflare и сторонним CDN.
- PDF поддерживает частичные запросы, обложки и миниатюры отображаются; сборка не содержит архивных PDF/JPEG страниц.
- Проверены узкий экран, три режима чтения, переходы по миниатюрам и прямые ссылки.
- Незалогиненный пользователь не загружает в приватный бакет; волонтёр не одобряет; куратор видит именно одобряемый файл.
- Разрыв после успешного PUT восстанавливается подтверждением без второй заявки.
- Параллельные одобрения оба попадают в каталог; сбой копирования или записи каталога устраняется повтором.
- Отклонение не удаляет файл сразу; очистка не затрагивает принятые выпуски.
- Новая версия frontend не стирает опубликованные файлы и каталог.

## 7. Переключение и откат

После тестирования российского сервера и TLS сохранить текущие DNS-настройки. В Cloudflare DNS заменить запись корня `@` на A с IP российского сервера и выбрать **DNS only**. Удалить конфликтующую старую CNAME/AAAA только для этого имени. NS можно оставить Cloudflare: DNS only направляет HTTP непосредственно на сервер. [Документация](https://developers.cloudflare.com/dns/proxy-status/).

Проверить `pilot-archive.ru` через несколько российских сетей, загрузку PDF и свежесть каталога. Доступность во всех сетях гарантировать нельзя.

Для отката хранить предыдущую сборку, каталог и DNS-конфигурацию. Возврат на Pages потребует действующей привязки custom domain и TLS: проверить их перед возвратом DNS. Во время отката не удалять новые заявки и объекты S3.

## Что потребуется от владельца

- Актуальный путь к репозиторию для реализации, проверки и Git-коммитов.
- Подтверждение варианта с сервером ради `pilot-archive.ru` без префикса; сервер пока не создан.
- Доступ к подготовленному Selectel-проекту или значения endpoint/пула/бакетов. Секреты вводить через защищённый механизм, не присылать текстом в переписку.

До выполнения этих шагов перенос не считать завершённым и не переключать production DNS.

## Команды восстановленного проекта

```sh
npm ci
npm run check
npm run dev
```

Сборки: `npm run build` → `dist` для Selectel; `npm run build:admin` → `dist-admin` для Cloudflare. `npm run deploy` публикует только админку. Автоматизация после merge описана в [GITHUB.md](GITHUB.md).

Первичная загрузка восьми восстановленных выпусков (AWS CLI, endpoint и ключи настроены в окружении):

```sh
Публичный архив уже находится в Selectel S3; новые выпуски публикуются backend-функцией после одобрения. Локальные PDF не являются источником production-каталога.
```

`manifest.json` публиковать отдельно после объединения с уже одобренными выпусками D1. Локальный manifest — исходный каталог для разработки, а не источник для перезаписи живого каталога.
