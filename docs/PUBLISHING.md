# Выкладка выпусков с цензурой

На сайте лежат только публичные версии выпусков (с чёрными плашками, см. [REDACTION.md](REDACTION.md)). Оригиналы хранятся в приватном бакете `pilot-archive-issues-private` под префиксом `originals/` (тот же ключ, что на сайте) и локально в `~/Downloads/Reading/pilot-archive/`.

## Где что лежит

| Что | Где |
| --- | --- |
| Публичный PDF и обложка | `pilot-archive-public`, ключ из `pdfUrl`/`coverUrl` в `archive/manifest.json` |
| Оригиналы | `pilot-archive-issues-private/originals/<тот же ключ>` |
| Заявки до одобрения | `pilot-archive-issues-private/pending/submissions/…` |
| Распознавание, решения, публичная версия | `~/Downloads/Reading/pilot-archive-fulltext-cache/<год>-<номер>-<серия>/` |

Перед `pilot-archive.ru` стоит Caddy на российском сервере 135.106.210.25 (журнал для статистики, SSH по ключу `~/.ssh/pilot_archive_gateway`), за ним публичный домен бакета Selectel (`…selstorage.ru`). Его кэш замечает замену объекта сам: сразу после выкладки сайт отдавал новые файлы с `age: 0`, сбрасывать ничего не пришлось.

### Почему загрузка идёт через сервер

Из-за границы загрузка в Selectel почти не работает: около 20 КБ/с на соединение, а запрос дольше 15 минут Selectel обрывает (`OperationAborted`), в том числе части многочастной загрузки. Пока PUT в ключ не закончен, Selectel отвечает на этот ключ 409, и выпуск пропадает с сайта; оборванный PUT оставляет обрезанный файл. Поэтому `publish-redacted.mjs`:

1. копирует файл на российский сервер по `scp` (по SSH из-за границы быстро: 17 МБ меньше чем за минуту);
2. сервер кладёт его `curl -T` во временный ключ `staging/…` приватного бакета по подписанной PUT-ссылке (её делает `scripts/presign-put.py` Python'ом из aws cli; ключей Selectel на сервере нет);
3. копирование на стороне Selectel ставит файл на место мгновенно, с `Cache-Control` и `Content-Disposition` (имя файла при сохранении — «ПП №01(0066)-5.01.2000.pdf»), временный ключ удаляется.

Ключ Selectel не может удалять объекты в публичном бакете (DeleteObject запрещён): ненужный файл там можно только перезаписать.

## Замена уже выложенных выпусков

1. Оригиналы скопированы в `originals/` (сделано 16.10.2026 для всех 28 выпусков на сайте):
   ```
   export AWS_PROFILE=selectel AWS_DEFAULT_REGION=ru-6 AWS_CA_BUNDLE=/etc/ssl/cert.pem
   aws --endpoint-url https://s3.ru-6.storage.selcloud.ru s3 cp --recursive \
     s3://pilot-archive-public/archive/ s3://pilot-archive-issues-private/originals/archive/ \
     --exclude '*' --include '*.pdf' --include '*.jpg'
   ```
2. Для каждого выпуска готова публичная версия: `npm run censor -- "<PDF>" --apply`.
3. План: `node scripts/publish-redacted.mjs`. Скрипт сверяет выпуски из манифеста сайта с кэшем и не пускает выпуск без публичной версии, без копии оригинала или с `redactions.json` новее публичной версии.
4. Выкладка: `node scripts/publish-redacted.mjs --apply` (или `--apply 2000-27` для одного выпуска). PDF кладётся по тому же ключу, манифест и D1 не меняются. Обложка пересобирается, только если изменился лист 1.
5. Проверить: `curl -sI https://pilot-archive.ru/<ключ>`, где `content-length` должен совпасть с размером публичной версии; открыть выпуск на сайте и посмотреть закрытое место.

Повторная правка выпуска: поправить `redactions.json`, `censor --apply`, снова шаги 3–5.

16.10.2026 так выложены все 28 выпусков сайта; старые копии оригиналов № 11, 12, 14 под `published/submissions/` (остались от миграции, удалить нельзя) перезаписаны публичными версиями.

## Новый выпуск

Одобрение в админке копирует файл заявки из приватного бакета в публичный как есть, поэтому цензура должна произойти **до** нажатия «Одобрить». Загружать PDF через админку из-за границы не нужно (загрузка в Selectel оттуда обрывается), заявку ставит скрипт.

1. Положить оригинал в `~/Downloads/Reading/pilot-archive/` под именем `ПП №NN(SSSS)-Д.ММ.ГГГГ.pdf`, выполнить `npm run censor -- "<PDF>"`, разобрать находки в `review.html` и просмотреть полосы глазами по [REDACTION.md](REDACTION.md), затем `npm run censor -- "<PDF>" --apply` и `node scripts/check-anchors.mjs <id>`.
2. `bash scripts/stage-issue.sh "<PDF>"`. Скрипт через российский сервер кладёт оригинал в `originals/archive/<год>/<slug>/issue-<uuid>.pdf`, публичную версию и обложку (лист 1, 350 px, JPEG 82, как делает админка) в `pending/submissions/<год>/<slug>/<uuid>.pdf` и `….pdf.cover.jpg`, и только потом добавляет в D1 заявку со статусом `pending`. Не пускает выпуск без публичной версии, с устаревшей публичной версией или с уже существующей заявкой.
3. Куратор нажимает «Одобрить» в админке. Worker копирует файл в публичный бакет и переписывает манифест, браузер распознаёт авторов по уже цензурированной версии (закрытые подписи в указатель не попадают).
4. Задать имя файла при скачивании и `Cache-Control` (одобрение их не ставит): копировать объект сам в себя с `--metadata-directive REPLACE --cache-control 'public,max-age=86400' --content-disposition "inline; filename=…; filename*=UTF-8''…"`.

Так 16.10.2026 добавлены № 33–35 за 2000 год.

Если выпуск всё же загружен через админку, его файл в `pending/` — оригинал: до одобрения заменить его публичной версией тем же путём через сервер (`scripts/presign-put.py`), иначе на сайт уйдёт оригинал. Надёжнее добавить в одобрение проверку метки `x-amz-meta-redacted`, которую ставит только цензура.

## Что ещё помнить

- `archive-catalog/checksums.json` описывает оригиналы, а не публичные версии.
- Публичный индекс авторов `archive/authors-index.json` содержит фамилии авторов и заголовки статей. Если заголовок или подпись закрыты, их надо убрать и оттуда.
- Удалять из публичного бакета нашим ключом нельзя, только перезаписывать.
- Браузерные тесты CI читают PDF с живого сайта (`vite.config.ts`, `PUBLIC_ARCHIVE_ORIGIN`): если выпуск № 01 на сайте сломан, падают и они.
