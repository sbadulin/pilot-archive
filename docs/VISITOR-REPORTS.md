# Посещения и поиск авторов

События публичного сайта обрабатываются на российском сервере Caddy. В Telegram
уходят только сводки. Вход в админку читателям группы не нужен.

## Что считаем

- Посетители за день: разные пары IP и User-Agent, открывшие `/` или `/index.html`.
- Открытия сайта: успешные запросы этих страниц, включая ответы 304 и параметры URL.
- Загрузки выпусков: запросы PDF без Range либо с диапазоном, начинающимся с нуля.
  Показываются общее число и пять самых популярных выпусков с номерами и годами.
  Это приблизительная оценка, кеш и повторы влияют на неё.
- Поиск: запрос из двух и более символов (две буквы ищут только ник целиком, например «ПТ») после паузы 1,2 секунды либо при выборе
  результата. Подряд одинаковый запрос внутри открытого поиска считается один раз.
- Выбор автора: нажатие на подсказку либо Enter. Это отдельная метрика.
- Поиски без результатов и популярные запросы.

Известные боты исключаются по User-Agent. Cookies и постоянные идентификаторы для
аналитики не создаются. Запросы `GET /_stats/author` идут только на `pilot-archive.ru`,
без cookies и Referer. Caddy отвечает 204 и записывает событие в свой журнал.
Ошибка отправки не мешает поиску. События можно подделать, поэтому это статистика
интереса читателей, а не система аудита.

В сводках недели и месяца показывается среднее дневное число посетителей.
Дневные уникальные посетители не выдаются за уникальных посетителей месяца.
Неполные периоды явно помечены. До включения сбора истории нет.

## Установка на сервере

Требуются Caddy, Python 3.10+, tzdata и logrotate. Для прежнего отчёта нужны jq
и GoAccess. Проверьте действующий `/etc/caddy/Caddyfile`: если upstream там задан
буквально, сохраните его. Не заменяйте его на пустую переменную `S3_PUBLIC_HOST`.

1. Сохраните резервную копию конфигурации Caddy.
2. Перенесите блок `log` и обработчик `@authorStats` из `deploy/Caddyfile`.
3. Установите `deploy/pilot-archive.logrotate` в `/etc/logrotate.d/pilot-archive`.
   Системный logrotate должен запускаться ежедневно. Используется `copytruncate`,
   чтобы Caddy продолжал писать в открытый файл; небольшое окно потери запросов
   при копировании допустимо для приблизительной статистики. Встроенная ротация
   Caddy отключена. Ежедневная ротация включает и пустые файлы, старые копии удаляются.
4. Установите `scripts/telegram-report.py` и `scripts/visitor-report.sh` в
   `/opt/pilot-reports/`. Создайте `/var/lib/pilot-reports` с правами 0700.
5. Выполните `python3 /opt/pilot-reports/telegram-report.py init` при включении журнала.
6. Проверьте Caddy через `caddy validate --config /etc/caddy/Caddyfile`, затем
   `systemctl reload caddy`. При изменении параметров уже используемого файла
   журнала Caddy может потребовать restart; первоначальное добавление журнала
   применяется reload.
7. Установите `deploy/pilot-reports.service` и `deploy/pilot-reports.timer`
   в `/etc/systemd/system/`. Выполните `systemctl daemon-reload`, затем
   `systemctl enable --now pilot-reports.timer`.

Журнал `/var/log/caddy/pilot-archive.log*` остаётся на сервере, хранится до 30 дней
при работающей ежедневной ротации. Сводки в `/var/lib/pilot-reports/days/` содержат
числа и счётчики запросов, без IP и User-Agent, поэтому месяцы из 31 дня не теряются
при удалении исходных журналов. Уже сохранённые дни не пересчитываются из неполных
журналов. После простоя сборщика больше 28 дней часть истории будет недоступна.

## Telegram

Создайте бота через @BotFather, добавьте его в нужную группу и отправьте
`/start@имя_бота`. Ответ на эту команду не предусмотрен, она позволяет обнаружить
группу через Telegram API. Права администратора и отключение Group Privacy не нужны.

На сервере, в интерактивном терминале:

```sh
sudo python3 /opt/pilot-reports/telegram-report.py configure
```

Токен вводится скрыто. Скрипт покажет имена и ID доступных групп, предложит выбрать
ID и сохранит токен в `/etc/pilot-reports.json` с правами 0600. Сообщения группы
не сохраняются и не выводятся. Никакие сообщения при настройке не отправляются.
Не передавайте токен аргументом командной строки и не добавляйте его в Git.
До окончания настройки токен хранится в `/etc/pilot-reports.pending.json` с правами
0600. При повторном запуске Enter использует сохранённый токен. После успешного
сохранения конфигурации черновик удаляется.

Сначала используется DNS-адрес `api.telegram.org`. Если TCP-соединение не установлено,
скрипт пробует резервный адрес Telegram `149.154.167.220`, сохраняя проверку сертификата
для `api.telegram.org`. Повтор выполняется до отправки HTTP-запроса, поэтому не
дублирует сообщение. Резервный адрес проверен с сервера 15 октября 2026 года.

Таймер собирает завершённые дни в 00:10 МСК, отправляет сводки в 09:00 МСК:

- ежедневно за вчера;
- по понедельникам за предыдущие понедельник–воскресенье;
- первого числа за предыдущий календарный месяц.

При следующем запуске после простоя отправляются последние ещё не отправленные
периоды. Одновременные запуски блокируются файловой блокировкой. Повторная отправка
одного периода подавляется файлом `deliveries.json`. При неоднозначной ошибке
Telegram запись помечается `uncertain`; автоматического повтора нет, чтобы не
дублировать сообщение. Проверьте группу и журнал сервиса прежде, чем вручную
удалить соответствующий ключ из `deliveries.json` для повтора.

Пока конфигурации бота нет, таймер только собирает сводки и ничего не отправляет.
Если открытий сайта, PDF, поисков и выборов авторов за период не было, сводка
не отправляется. Отсутствие сообщения не следует использовать как проверку
работоспособности сервиса; для этого нужен статус systemd.

## Отправка через Cloudflare при нестабильном доступе к Telegram

На production используется отдельный Worker `pilot-archive-reports`. Российский
сервер отправляет ему только готовый текст сводки через HTTPS. Worker проверяет
секретный ключ и пересылает сообщение в единственную группу из своих настроек.
Он не получает журналы, IP или User-Agent посетителей. Адрес отправителя запроса
к Worker принадлежит серверу. Токен бота хранится в Cloudflare Secrets, а также
в защищённой конфигурации российского сервера. Логи запросов Worker отключены.

Первичная установка или обновление кода Worker:

```sh
wrangler deploy --config deploy/telegram-relay/wrangler.toml
```

После сохранения токена на сервере и определения ID группы выполните на рабочем
компьютере с авторизацией Cloudflare:

```sh
python3 scripts/configure-telegram-relay.py \
  --server root@SERVER --identity ~/.ssh/KEY \
  --chat-id=-100GROUP_ID --relay-url https://WORKER.workers.dev
```

Скрипт получает токен по SSH только в память процесса и передаёт секреты Wrangler
через stdin. Он не печатает токен и не создаёт его копию на рабочем компьютере.
На сервере сохраняются URL и ключ relay. При ротации токена повторите настройку
секретов Worker этой же командой. Worker обновляется отдельно от frontend.
Защищённый `/health` проверяет соединение Worker с Telegram без отправки сообщения.

## Обновление сайта и проверки

После публикации frontend с `src/authorAnalytics.ts` выполните на сервере:

```sh
sudo python3 /opt/pilot-reports/telegram-report.py enable-author-tracking
```

Это отметит дату начала учёта поиска в отчётах. Проверки без отправки сообщений:

```sh
sudo python3 /opt/pilot-reports/telegram-report.py collect
sudo python3 /opt/pilot-reports/telegram-report.py report --period day
sudo python3 /opt/pilot-reports/telegram-report.py report --period week
sudo python3 /opt/pilot-reports/telegram-report.py report --period month
systemctl list-timers pilot-reports.timer
journalctl -u pilot-reports.service
```

`--date YYYY-MM-DD` задаёт опорную дату: например, `--period month --date 2026-11-01`
выведет октябрь. Отчёты используют московские календарные сутки.

Старый `visitor-report.sh` остаётся доступен для быстрой сводки. Его GoAccess HTML
может содержать IP, поэтому его нельзя выгружать с сервера как обезличенную сводку.
Для группы используйте только текст из `telegram-report.py`.

Тесты: `python3 -m unittest discover -s tests -p 'test_*.py'` и `npm run check`.
